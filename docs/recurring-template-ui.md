# Recurring template UI clarity

Every visible binding is `recurringForm.<key>`. The same key is sent in the request, validated by `RecurringExpenseTemplateRequest`, and stored in `recurring_expense_templates.<key>`:

| Label | Key | Actual meaning / validation |
|---|---|---|
| Template Name | template_name | Human-readable template name; required string, max 255. |
| Expense Category | expense_category_id | Linked expense_categories record; required integer, checked within the business. |
| Expense Account | expense_account_id | Linked accounts record; required integer, checked as active expense account within the business. |
| Frequency | frequency | Stored recurrence frequency: daily, weekly, monthly, quarterly, half_yearly, yearly, custom. Required. |
| Amount | amount | Stored template expense amount (decimal 15,2); required numeric, minimum 0.01. Existing hidden tax_type/gst_rate settings are preserved. |
| Next Run Date | next_run_date | Stored next scheduled run date; required date. It is not start_date, which remains a separate existing hidden field. |
| Status | status | Stored lifecycle state: active, paused, stopped. Required; inactive is not supported. |

## Changes

- `resources/js/Pages/Accounting/Expenses.vue`: seven associated visible labels; name/amount placeholders; amount/date helpers; four-column desktop grid and existing mobile stacking; primary Save Template button; explicit saved-template heading, table headers, category/account names, empty state, pagination and Edit. Status changes use Edit then Save Template. Errors appear beside visible fields and in an alert (including errors for hidden fields). Success immediately inserts/replaces the returned template without depending on unrelated module reloads. The saved ID is retained. Editing preserves all existing hidden values and converts serialized dates back to Kolkata calendar dates without shifting the day.
- `app/Services/ExpenseIncomeService.php`: eager-loads the existing account relationship for list/save responses so mapped account names remain available, including when an account is absent from active choices. No calculation or generation changes.
- `tests/frontend/recurring-template.test.mjs`: feedback, duplicate-click protection, saved ID reuse, hidden-setting/date preservation and existing status update coverage.
- `tests/Feature/ExpenseIncomeCategoriesTest.php`: recurring required validation, create/list mappings and status update tests; checks no expense or journal is generated by saving.
- Generated Vite assets/manifest and this report.

## Existing support and limitations

GET `/app/accounting/recurring-expenses/list`, POST `/app/accounting/recurring-expenses` and PUT `/app/accounting/recurring-expenses/{template}` already existed. The list is paginated at 20 rows. Editing and setting active/paused/stopped were already supported by PUT. No delete endpoint exists, so none was exposed.

The original UI captured field-keyed errors but did not render them on Recurring and had no success feedback. Both are fixed. No schema, recurring-generation, scheduler, voucher or posting behavior was changed. The inspected repository contains template persistence and a recurring runs model/table, but no implemented recurring generation command/job or recurring scheduler entry; helper text deliberately does not promise that saved dates trigger automatic expense creation.
